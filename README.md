# AI Recogniser

[![CI](https://github.com/StAlexes/ai-recogniser/actions/workflows/ci.yml/badge.svg)](https://github.com/StAlexes/ai-recogniser/actions/workflows/ci.yml)

Локальное Windows-приложение для распознавания русской речи из mp3/mp4: очередь задач в трее,
GigaAM v3, локальные саммари, база знаний и глоссарий. Без облака по умолчанию.

**Статус:** M0 завершён; M1 в работе. Уже работает реальное распознавание mp3/mp4, VAD-нарезка
длинных записей по сегментам, очередь с прогрессом, текст в UI и интеграция с локальным `ragkb`;
нативная сборка содержит ASR-стек, VAD и ffmpeg. Пока нет таймкодов, SQLite-очереди,
отмены/повтора и экспорта SRT/VTT — это следующие шаги M1.
План: [`docs/PLAN.md`](docs/PLAN.md). История версий: [`CHANGELOG.md`](CHANGELOG.md).
Замеры GigaAM: [`docs/M0-NOTES.md`](docs/M0-NOTES.md). Сборка exe: [`docs/BUILD.md`](docs/BUILD.md).
Vulkan/iGPU: [`docs/VULKAN-NOTES.md`](docs/VULKAN-NOTES.md).

## Что уже работает

- Ядро на `127.0.0.1` со случайным портом и сессионным токеном: health, настройки, профиль ПК, каталог моделей.
- Окно WebView2 с Fluent UI: очередь (drag&drop файлов), база знаний, модели, настройки, светлая/тёмная тема.
- Трей, закрытие в трей, уведомления, single-instance, автозапуск.
- **Распознавание:** загрузка mp3/mp4 и других аудио/видео форматов, конвертация через ffmpeg,
  GigaAM v3 e2e CTC int8 на CPU, прогресс по этапам, результат в `.txt` и в интерфейсе.
- **VAD-нарезка:** длинные записи делятся Silero VAD v5 (ONNX, MIT) на речевые сегменты по
  паузам, каждый сегмент распознаётся отдельно и текст склеивается. Есть резервная нарезка
  фиксированными окнами, если VAD-модель недоступна.
- **Очередь:** загрузка файла, задача со статусом, фоновый worker, восстановление завершённых
  задач после перезапуска. Очередь пока в памяти, один worker; SQLite — следующий шаг.
- **База знаний:** живой статус `ragkb`, семантический поиск и опциональный вопрос-ответ с
  источниками. RAG — внешний локальный сервис, индекс не копируется в приложение.
- **Нативный exe:** оболочка, ядро, Python-рантайм, UI, ONNX Runtime, `onnx-asr` и ffmpeg внутри;
  Python на целевой машине не нужен.
- GigaAM v3 e2e CTC int8: **RTFx 56.8** на Ryzen 7 8845H, **352 МБ** RSS — CPU быстрее iGPU Radeon 780M.

## Требования для разработки

- Windows 10 1809+ / Windows 11, WebView2 Runtime (на Windows 11 уже установлен).
- Python 3.12+ (проверено на 3.13).
- Node.js 20.19+ и npm — только для сборки UI.
- Для RAG — отдельно запущенный локальный `ragkb` на `http://127.0.0.1:8000`
  (адрес и лимит источников настраиваются в приложении).

## Стек

- **Ядро:** Python 3.12+, FastAPI, ONNX Runtime, `onnx-asr`, httpx на `127.0.0.1` со случайным
  портом и токеном. SQLite и менеджер моделей — в следующих итерациях.
- **UI:** React + TypeScript + Fluent UI v9, собирается Vite в `ui/dist`.
- **Оболочка:** WebView2 (pywebview), трей, single-instance, автозапуск.
- **ASR:** GigaAM v3 e2e CTC int8 (MIT), CPU execution provider.
- **RAG:** внешний локальный `ragkb` (HTTP); приложение не импортирует его индекс и не требует
  его для распознавания.
- **Модели:** GigaAM v3 e2e CTC int8 (MIT); Multilingual/Whisper/LLM — опции следующих этапов.

## Установка для разработки

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -e ".[dev,shell,asr]"

# UI
cd ui
npm.cmd install
npm.cmd run build
cd ..

# быстрый запуск из исходников (ядро + окно + трей)
run.cmd

# ядро отдельно (dev, без токена)
.\.venv\Scripts\python -m airec --port 8765 --no-auth

# приложение целиком вручную
.\.venv\Scripts\python shell\main.py
```

`run.cmd` запускает решение «на лету»: проверяет venv, при отсутствии `ui\dist` собирает UI и
открывает приложение из исходников. Дополнительные аргументы передаются в `shell\main.py`.
UI в dev-режиме: `npm.cmd run dev` (Vite проксирует `/api` на `127.0.0.1:8765`).

При первом распознавании `onnx-asr` скачает модель GigaAM (~215 МБ) и Silero VAD (~2 МБ) в кэш
Hugging Face. После этого распознавание работает офлайн. Если ffmpeg нет в `PATH`,
используется бинарник из `imageio-ffmpeg`; его же получает собранный exe.

## База знаний (RAG)

RAG не входит в поставку и не обязателен для распознавания. Приложение подключается к уже
запущенному локальному `ragkb`:

1. Запустите `ragkb` так, чтобы его API был доступен на `http://127.0.0.1:8000`.
2. Откройте «Настройки» → «База знаний» и проверьте адрес; при необходимости выключите интеграцию.
3. На странице «База знаний» доступны статус, число чанков, поиск и кнопка «Спросить RAG».

Если сервис недоступен, страница показывает понятную ошибку, а очередь и распознавание
продолжают работать. Индекс и модель `ragkb` остаются в его каталоге; приложение их не копирует.

## Сборка нативного exe

На целевой машине нужен только WebView2 Runtime (на Windows 11 уже есть) и права на запись
в папку данных. Python, Node.js и Visual Studio не требуются.

```powershell
.\.venv\Scripts\pip install -e ".[dev,shell,asr,build]"
build.cmd

# повторная сборка без пересборки UI
build.cmd -SkipUi
```

Результат — папка `dist\AI Recogniser\` с `AI Recogniser.exe` и `_internal\`. Запускайте exe
из этой папки; переносить нужно папку целиком. Portable-режим: положите пустой файл
`portable.flag` рядом с exe — данные будут в `.\data`, реестр не используется.

Текущая сборка: `AI Recogniser.exe` ~15 МБ, `_internal` ~211 МБ; внутри есть ONNX Runtime,
`onnx-asr`, GigaAM-зависимости и ffmpeg. Модель GigaAM в exe не входит и скачивается при первом
запуске. Сборка не подписана, поэтому SmartScreen при первом запуске может показать
предупреждение. Подробности, состав поставки и проверки — в [`docs/BUILD.md`](docs/BUILD.md).

## Данные и приватность

- Установленный режим: `%LOCALAPPDATA%\AIRecogniser` (модели, кэш, логи, результаты, `config.json`).
- Portable: файл `portable.flag` рядом с exe → данные в `.\data`, реестр не трогаем.
- API доступен только на loopback и требует токен из `session.json`; наружу ничего не уходит,
  кроме явных загрузок моделей/обновлений и обращений к локальному RAG, если он включён.
- Секреты и токены не пишутся в логи.
