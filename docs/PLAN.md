# AI Recogniser — план разработки

**Версия документа:** 1.4
**Дата:** 2026-10-24
**Статус:** M0 выполнен (2026-10-23); M1 частично (ASR, VAD-нарезка, очередь, RAG-интеграция, cmd-запуск и сборка); ключевые решения зафиксированы (см. §17.1 и ADR-010)
**Целевая платформа:** Windows 11 (Fluent 2 / Mica), Windows 10 22H2+ (fallback-тема)

---

## 1. Продукт в одном абзаце

AI Recogniser — локальное приложение для Windows, которое живёт в трее, принимает mp3/mp4 (и другие форматы через ffmpeg), ставит задачи распознавания в очередь, транскрибирует русскую речь моделью GigaAM v3 (Сбер, MIT), при необходимости извлекает аудио из видео, делает саммари и разбор содержания локальной LLM, использует пользовательскую базу знаний и глоссарий для корректной интерпретации терминов, складывает результаты в файлы и присылает уведомление по завершении. Полностью офлайн по умолчанию, переносится на другой компьютер установщиком или portable-сборкой.

## 2. Границы работ

### 2.1 Входит в v1.0

- Трей-приложение с фоновой очередью и автозапуском (опционально).
- Вход: `mp3`, `mp4`, `m4a`, `wav`, `flac`, `ogg`, `opus`, `mkv`, `mov`, `webm`, `avi` (видео — через ffmpeg).
- Извлечение аудиодорожки из контейнера, нормализация, VAD-нарезка, таймкоды.
- ASR: GigaAM v3 e2e CTC int8 (пунктуация и нормализация «из коробки»), опционально Whisper large-v3-turbo как мультиязычный fallback.
- Очередь: приоритеты, пауза/возобновление, отмена, повтор, восстановление после падения, ограничение параллелизма.
- Экспорт: `txt`, `md`, `srt`, `vtt`, `json`, опционально `docx`.
- LLM: саммари, структурный разбор (решения / задачи / вопросы / риски), Q&A по транскрипту, «редактор текста» с глоссарием. По умолчанию — локально; внешний OpenAI-совместимый API — опция с явным включением (ADR-008).
- База знаний: импорт pdf/docx/txt/md, чанкинг, эмбеддинги, гибридный поиск, цитаты-источники, терминологический словарь.
- Диаризация спикеров (beta, на ONNX, без torch) — кто говорил и когда.
- Уведомления Windows (toast) с действиями, меню трея, прогресс на иконке.
- Мастер первого запуска: экспресс-тест ПК → рекомендация моделей → скачивание → демо-проба.
- Установщик с опциями и portable-режим. Менеджер моделей (докачка, проверка SHA-256, офлайн-импорт).
- Версионирование, CHANGELOG, миграции БД/конфига, диагностика.

### 2.2 Не входит в v1.0 (осознанно)

- Распознавание в реальном времени с микрофона (отдельная фича, архитектурно готовы).
- Прожиг субтитров в видео, видеомонтаж.
- Облачная синхронизация, мобильные клиенты, macOS/Linux desktop.
- Многопользовательский режим и веб-доступ — **фаза 2** (см. §16), но архитектура закладывается сразу.
- Автоматическая загрузка на сторонние сервисы (только явные интеграции по запросу).

## 3. Ключевые сценарии

1. **«Созвон в mp4»** — перетащил файл в окно → приложение извлекло дорожку → через N минут тост «Готово: 42 мин, 3 спикера» → клик открывает транскрипт и саммари с задачами.
2. **«Пачка лекций»** — drag&drop 30 файлов → очередь, приоритеты, пауза на ночь → утром все результаты в папке и в истории.
3. **«Термины компании»** — загрузил регламенты и глоссарий в базу знаний → ASR-постобработка исправляет «битрикс» → «Битрикс24», LLM объясняет фразы контекстом, а не догадками.
4. **«Ноут на батарее»** — приложение само ставит очередь на паузу (опция), не греет и не жрёт заряд.
5. **«Другой компьютер»** — установщик, мастер, тест ПК, скачивание моделей; или portable-папка с флешки без следов в реестре.

## 4. Технические решения (ADR)

### ADR-001. Ядро на Python 3.12 + ONNX/GGUF, без PyTorch

**Решение:** ядро — Python 3.12 (embeddable runtime), инференс только ONNX Runtime и llama.cpp. PyTorch в поставку не входит.

**Почему:** весь нужный стек существует в ONNX: GigaAM v3 (onnx-asr), Silero VAD, диаризация (sherpa-onnx), эмбеддинги (fastembed). Это экономит ~2.5–3 ГБ, убирает CUDA/torch-конфликты и делает сборку переносимой.

**Следствия:** свои обёртки для пайплайна; экспорт новых моделей в ONNX — отдельный скрипт в `tools/export/`.

### ADR-002. Ядро-сервис + веб-UI + WebView2-оболочка

**Решение:** три слоя:
- `core` — FastAPI на `127.0.0.1:<random>` (очередь, пайплайн, LLM, RAG, файлы);
- `ui` — React 19 + TypeScript + **Fluent UI v9** (MIT), собирается в статику;
- `shell` — тонкий десктоп-хост на pywebview/WebView2: окно, трей, single-instance, автозапуск, тосты.

**Почему:** один UI-код для десктопа и будущего серверного/браузерного режима (фаза 2 почти бесплатно); Fluent UI v9 даёт аутентичные контролы Win11; WebView2 есть на Win11 и ставится на Win10.

**Альтернативы:**
| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| .NET 10 + WinUI 3 + ONNX/LLamaSharp | нативность, размер | переписывание ML-пайплайна, диаризация, нет переиспользования для сервера | резерв |
| PySide6 + qfluentwidgets | один язык | UI-итерации медленнее, отдельный веб-UI для сервера | нет |
| Electron | зрелость | +150 МБ, память, безопасность | нет |
| Tauri v2 | лёгкий, нативный трей | Rust-тулчейн + Python sidecar, дольше до MVP | возможная замена оболочки позже |

**Следствия:** оболочка не содержит бизнес-логики и легко заменяется на Tauri/WinUI без переделки UI и ядра.

### ADR-003. Очередь и состояние — SQLite (WAL)

Одна БД `app.db`: задачи, сегменты, саммари, настройки, модели, KB, события. Никаких внешних брокеров. Восстановление после падения: задача со статусом «в работе» при старте переводится в «прервана → повтор».

### ADR-004. LLM — llama.cpp `llama-server` как дочерний процесс, API OpenAI-совместимый

Провайдеры за интерфейсом `LLMProvider`: `llamacpp-local` (по умолчанию), `ollama`, `openai-compatible` (внешний API — только по явному включению). Это позволяет менять модель и рантайм без переделки логики.

### ADR-005. Модели — вне папки установки, реестр с версиями и SHA-256

`%LOCALAPPDATA%\AIRecogniser\models` (или `<portable>\data\models`). `models/manifest.json` описывает id, версию, URL, размер, хеш, лицензию, требования к RAM. Докачка с resume, зеркала, офлайн-импорт.

### ADR-006. Установщик Inno Setup, per-user без админа, + portable zip

Inno Setup 6: мастер с опциями, компонентами, проверкой места, WebView2 bootstrapper, автозапуск, контекстное меню Проводника («Распознать в AI Recogniser»), ассоциации — опционально. Portable: флаг `portable.flag`, данные рядом с exe, ничего в реестре.

### ADR-007. Версионирование — SemVer + Keep a Changelog

Единый источник версии — `pyproject.toml` → генерируется `app/airec/version.py`, подставляется в установщик, UI и `/api/v1/health`. Git-теги `vX.Y.Z`. CHANGELOG пополняется накопительно, старые записи не переписываются.

### ADR-008. Локальная LLM по умолчанию, внешние API — явная опция

**Решение:** базовый режим — `llama.cpp` + GGUF на этом же ПК. В настройках можно добавить внешний провайдер (OpenAI-совместимый, YandexGPT, GigaChat и т. п.), но только осознанным действием пользователя.

**Почему:** приватность — ключевая ценность продукта; при этом на слабых ПК внешняя LLM может быть единственным способом получить качественное саммари.

**Правила:**
- Автоматического fallback на внешний API нет — только явное переключение профиля.
- Перед первым запросом — предупреждение «текст покинет компьютер», отдельный чекбокс.
- Ключи хранятся в Windows Credential Manager (не в `app.db`/логах).
- В `meta.json` результата фиксируется, где считалось саммари (`local` / `external:<provider>`), в UI — бейдж.
- В логах и диагностике — без содержимого текста и ключей.

### ADR-009. Audio-LLM (GigaChat Audio) — эксперимент, не базовая зависимость

**Контекст:** MIT-модель GigaChat Audio 10B-A1.8B умеет эмоции, таймкоды и Q&A прямо по аудио, но требует ~22 ГБ (bf16) + PyTorch/vLLM + CUDA; GGUF/ONNX для аудио-части нет, llama.cpp её не поддерживает.

**Решение:** в v1.0 не включаем. После релиза — спайк `AudioLLMProvider` за фича-флагом: только машина с NVIDIA ≥16 ГБ VRAM или внешний API. Основным остаётся конвейер «ASR → текстовая LLM → RAG».

**Почему:** вес и требования несовместимы с «лёгким приложением на любом ноуте» и ADR-001; качество ASR ниже GigaAM v3; выигрыш — в эмоциях и поиске по аудио, а это не ядро v1.0.

**Критерии эксперимента:** на 3–5 реальных записях сравнить WER/пунктуацию, точность таймкодов, эмоции/диаризацию, latency и VRAM. При убедительном выигрыше — отдельный GPU-режим или облачная интеграция, но не замена ASR.

### ADR-010. RAG — внешний локальный HTTP-сервис, без копирования индекса

**Контекст:** у пользователя уже работает `ragkb` с готовым индексом и генеративной моделью. Копировать индекс в AI Recogniser или дублировать чанкинг/эмбеддинги на старте M1 невыгодно: это увеличивает поставку, создаёт второй источник истины и требует переиндексации при изменении документов.

**Решение:** приложение подключается к уже запущенному `ragkb` по HTTP (`/health`, `/search`, `/ask`). Адрес, число источников и включение интеграции задаются в настройках. `ragkb` — первый адаптер; интерфейс клиента расширяемый, чтобы позже поддержать другой локальный RAG-сервис.

**Почему:** сохраняется автономность и приватность, индекс не копируется, распознавание не зависит от доступности RAG. Недоступный сервис показывает понятную ошибку, но не ломает очередь.

**Ограничения:** RAG не входит в поставку; пользователь сам запускает сервис и отвечает за его модели/лицензии. В v1.0 нет импорта документов и переиндексации внутри AI Recogniser — это зона `ragkb`.

## 5. Модели: что берём и почему

### 5.1 Рекомендуемый набор

| Роль | Модель | Размер (int8/q4) | Лицензия | Комментарий |
|---|---|---|---|---|
| **ASR (RU, основная)** | **GigaAM v3 e2e CTC** (`istupakov/gigaam-v3-onnx`, 214 МБ int8) | 214 МБ | MIT (веса), MIT (код) | пунктуация + нормализация, RTFx ≈ 59 на 9800X3D; на 8845H ожидаемо 25–40 |
| ASR (качественнее, медленнее) | GigaAM v3 e2e RNN-T | ~216 МБ | MIT | WER ниже (8.4 vs 9.2 avg), декод медленнее (RTFx ≈ 43) |
| ASR (CIS/EN, опция) | GigaAM Multilingual CTC 220M int8 (large 600M — 564 МБ) | 214 / 564 МБ | MIT | KZ/KG/UZ + EN, без пунктуации (char CTC); ONNX-порты istupakov, поддержка в onnx-asr |
| ASR (мультиязычный fallback) | Whisper large-v3-turbo (faster-whisper, int8) | ~1.6 ГБ | MIT | опция; для языков вне покрытия GigaAM и как «второе мнение» |
| VAD | Silero VAD v5 (ONNX) | ~2 МБ | MIT | нарезка длинных файлов, отсечение тишины |
| Диаризация | pyannote segmentation-3.0 ONNX + CAM++ (3D-Speaker) | ~35 МБ | MIT / Apache-2.0 | через sherpa-onnx, без torch, beta |
| Эмбеддинги | multilingual-e5-small (ONNX) | ~118 МБ | MIT | база знаний; e5-large опционально |
| LLM (8 ГБ RAM) | Qwen3-4B-Instruct q4_k_m | ~2.6 ГБ | Apache-2.0 | быстрый, достаточный для саммари |
| LLM (16–32 ГБ RAM) | **T-lite-it-2.1 8B q4_k_m** (T-Bank, Qwen3-based, RU) | ~5 ГБ | проверить перед релизом | основной кандидат для русского |
| LLM (альтернатива) | YandexGPT-5-Lite-8B-instruct q4 | ~5 ГБ | проверить перед релизом | A/B на корпусе пользователя |
| Рантайм LLM | llama.cpp `llama-server` (CPU + Vulkan) | ~30–60 МБ | MIT | Vulkan — опция для iGPU |
| Медиа | ffmpeg/ffprobe static (LGPL — цель; текущая сборка imageio-ffmpeg — GPLv3) | ~80 МБ | LGPL 2.1+ / GPLv3 | декод, извлечение, нормализация |

> **Важно:** GigaAM v1 распространялся по NC-лицензии. Для продукта используем **только v2/v3 (MIT)**. Перед релизом фиксируем лицензии всех весов в `docs/LICENSES.md`. Целевая сборка ffmpeg — LGPL; текущий бинарник из `imageio-ffmpeg 0.6.0` собран с GPLv3, поэтому до релиза нужна замена или GPL-совместимая поставка.

### 5.2 Почему GigaAM, а не Whisper

- Русский: средний WER 9.2 (v3 CTC) / 8.4 (RNN-T) против 25.1 у Whisper на их же бенчмарке; на «живой» речи и колл-центре разрыв ещё больше.
- 214 МБ против 1.6 ГБ, работает на CPU ноутбука, не требует GPU.
- E2E-вариант сразу даёт пунктуацию и числа — меньше постобработки и лучше саммари.
- MIT — можно поставлять в коммерческом/внутреннем продукте.

**Мультиязычная ветка (GigaAM Multilingual, июль 2026).** Отдельная линейка 220M/600M, MIT, 5 языков (RU, EN, KK, KY, UZ), 2 млн часов предобучения. Для русского качества сопоставимы с v3 (CV 7.1 / FLEURS 4.4 / internal 7.6 у 220M; large — 5.1 / 3.0 / 6.0), но это **char-CTC без пунктуации и нормализации**, поэтому дефолтом для RU остаётся v3 e2e CTC. Multilingual берём как опциональный движок для KZ/KG/UZ/EN и смешанной речи; пунктуацию при необходимости восстанавливает постобработка/LLM. ONNX int8 уже готов (214 МБ / 564 МБ), поддержка в onnx-asr есть.

**GigaChat Audio 10B-A1.8B (июль 2026).** Аудио-нативная MoE-модель (10B всего / 1.8B активных) поверх GigaChat 3.1 Lightning: эмоции, temporal grounding с таймкодами, audio QA, до 3 ч аудио в контексте (64k токенов), MIT. Но: **22 ГБ весов bf16**, аудиоэнкодер 2.2 ГБ, запуск через PyTorch/vLLM и CUDA; GGUF/ONNX для аудио-части нет, llama.cpp её не поддерживает; ASR по русскому хуже GigaAM v3 (Golos crowd WER 14.7, farfield 9.7). Для ноутбука с iGPU и портативной поставки — не вариант в v1.0. Держим как **экспериментальный «аудио-аналитик»** после релиза: только GPU ≥16 ГБ или внешний API, за фича-флагом (ADR-009).

### 5.3 Профили по железу (предварительно)

| Профиль | RAM | ASR | LLM | Диаризация | Ожидание |
|---|---|---|---|---|---|
| C (минимум) | 8 ГБ, 4 ядра | GigaAM v3 e2e CTC int8 | Qwen3-4B q4 | выкл | 1 ч аудио ≈ 6–10 мин |
| B (типовой) | 16 ГБ, 6–8 ядер | GigaAM v3 e2e CTC int8 | T-lite 8B q4 (ctx 8k) | вкл | 1 ч ≈ 3–5 мин, саммари ≈ 1–2 мин |
| A (референс: текущий ноут) | 32 ГБ, 8845H, 780M | GigaAM v3 e2e CTC int8 (CPU; Vulkan/DML — только эксперимент) | T-lite 8B q5 / 14B q4 | вкл | 1 ч ≈ 1.5–3 мин |

Точные числа фиксируем после M5 (бенчмарк), а не обещаем заранее.

**Замер M0 (2026-10-23, референсный ноут):** GigaAM v3 e2e CTC int8, клип 11.3 с — загрузка 1.7 с, инференс 0.199 с, **RTFx 56.8**, peak RSS 352 МБ, пунктуация корректная. DirectML в отдельном runtime дал **RTFx 49.3 и 622 МБ RSS** — на Radeon 780M iGPU-ускорение проигрывает CPU, дефолт остаётся CPU. На длинных файлах RTFx будет ниже из-за VAD/чанкинга. Детали: `docs/M0-NOTES.md`.

**Vulkan (2026-10-23):** официального Vulkan EP у ONNX Runtime нет; WebGPU EP на Windows идёт через Dawn/D3D12. Для GigaAM оставляем CPU. Для LLM Vulkan-бэкенд `llama.cpp` — опция после отдельного бенчмарка; Whisper в текущую сборку не входит. Подробности и ссылки: `docs/VULKAN-NOTES.md`.

## 6. Архитектура

```
                    ┌──────────────────────────────┐
                    │  shell (pywebview/WebView2)  │
                    │  окно · трей · тосты · авто  │
                    └──────────────┬───────────────┘
                                   │ http://127.0.0.1:PORT (token)
                    ┌──────────────▼───────────────┐
   React + Fluent UI │        FastAPI (core)       │  SSE/WebSocket — прогресс
        (dist)       │  /jobs /models /kb /settings │
                    └───┬───────┬────────┬─────────┘
                        │       │        │
             ┌──────────▼─┐ ┌───▼────┐ ┌─▼──────────────┐
             │ Job queue  │ │ Models │ │ KB / RAG       │
             │ SQLite WAL │ │registry│ │ sqlite-vec     │
             └──────┬─────┘ └───┬────┘ └─┬──────────────┘
                    │           │        │
      ┌─────────────▼───────────▼────────▼─────────────┐
      │                 Worker pool                     │
      │ ffmpeg → VAD → ASR(GigaAM) → post → LLM → export│
      └───┬───────────┬──────────────┬─────────────┬────┘
          │           │              │             │
     onnx-asr    sherpa-onnx    llama-server    fastembed
     (GigaAM)    (VAD/diar)     (GGUF, HTTP)    (ONNX)
```

**Процессы:** `AI Recogniser.exe` (shell) → запускает тот же exe с `--core-worker` (frozen core) на свободном порту, ждёт `/health`, затем открывает окно. В dev-режиме вместо exe используется `python -m airec`. Падение core → shell перезапускает (до 3 раз) и показывает диагностику.

**Single instance:** именованный mutex + лок-файл с портом; второй запуск открывает окно первого и передаёт ему файлы через named pipe/HTTP.

**Безопасность локального API:** bind только `127.0.0.1`, случайный порт, bearer-token в `%LOCALAPPDATA%\AIRecogniser\session.json` (права только для пользователя), строгая валидация путей (никаких `..`), ffmpeg вызывается списком аргументов (без shell).

## 7. Пайплайн обработки

```
add(file) → probe(ffprobe) → hash → [video? extract audio] → normalize → VAD-чанки
   → ASR по чанкам (8–30 с, перекрытие) → склейка с таймкодами
   → диаризация (опц.) → постобработка (глоссарий, числа, пунктуация)
   → LLM-редактор (опц.) → саммари map-reduce (+RAG) → экспорт → уведомление
```

**Детали:**
- Аудио всегда в `16 kHz mono PCM s16le` (требование GigaAM), видео — `-vn`.
- Громкость: `loudnorm` (EBU R128), защита от клиппинга.
- VAD-нарезка: silero, min 5 с, max 30 с, пауза ≥ 300 мс; храним абсолютные таймкоды.
- Прогресс: по длительности обработанных чанков, ETA по скользящему среднему RTFx.
- Кэш: результаты чанков в `cache/<job>/<chunk>.json` → повтор с места падения, возобновление после kill.
- Сбои: битый файл/нет дорожки/DRM → понятная ошибка в UI, файл не блокирует очередь.
- Длинные файлы (3 ч+): чанки по 10–15 мин на уровне «сегментов», память ограничена.
- Приоритеты: интерактивные задачи (перетащил вручную) выше пакетных; FIFO внутри приоритета.
- Параллелизм: ASR 1 воркер (память), LLM 1, ffmpeg 2; настраивается, авто-подбор по RAM.
- Пауза очереди, «не работать на батарее», «не работать при >X% CPU» (опции).

**Именование результатов:**
```
results/2026-10-23_14-05_Совещание_по_бюджету/
  transcript.txt | .md | .srt | .vtt | .json
  summary.md
  meta.json          # модель, версия, параметры, длительность, хеш, RTFx
  audio.wav          # опционально (настройка «хранить нормализованное аудио»)
```

## 8. LLM и база знаний

### 8.1 Саммари

- **Map-reduce:** транскрипт режется по смысловым блокам (по VAD-паузам/таймкодам, ~3–4 тыс. токенов), для каждого — конспект, затем свёртка в финальный JSON.
- **Структура ответа (валидируется по схеме):**
  - `tl_dr` (3–5 предложений), `topics[]`, `decisions[]`, `action_items[]` (owner, deadline, формулировка), `questions_open[]`, `risks[]`, `quotes[]` (цитата + таймкод + спикер).
- **Анти-галлюцинации:** temperature 0.2, «не добавляй факты вне транскрипта», каждое решение/задача — со ссылкой на таймкод; при провале JSON-схемы — ретрай и экстрактивный fallback (частотные формулировки + цитаты).
- **Промпты** — версионируются в `app/airec/llm/prompts/*.md`, версия попадает в `meta.json`.
- **Q&A по файлу:** чат по транскрипту с обязательными ссылками на таймкоды; ответ «в тексте нет» при отсутствии подтверждения в тексте.

### 8.2 База знаний и глоссарий

- Импорт: pdf (текстовый слой; OCR — вне v1), docx, txt, md, csv. Теги, папки, вкл/выкл источника.
- Чанкинг: 400–800 токенов, overlap 15%, сохранение заголовков/страниц для цитат.
- Эмбеддинги: multilingual-e5 (ONNX), нормализация, хранение в sqlite-vec; fallback — numpy-поиск при недоступности расширения.
- Поиск: гибрид (вектор + BM25/FTS5 по русскому), top-k → в промпт с номерами источников; в ответе — сноски `[1]`.
- **Глоссарий** — отдельный слой: пары «как слышится → как правильно» + пояснения. Применяется (а) детерминированно к тексту ASR, (б) в промпте редактора, (в) в саммари. Импорт/экспорт CSV, версии словаря.
- Индексация инкрементальная, с очередью и прогрессом; переиндексация при смене модели эмбеддингов (предупреждение +фоновая миграция).

### 8.3 Рантайм LLM

- `llama-server.exe` с `--model <gguf> --ctx-size N --threads N --host 127.0.0.1 --port <p>`.
- Выбор бэкенда: CPU (по умолчанию), Vulkan (iGPU, опция «ускорение на iGPU»), позже CUDA/DirectML при наличии.
- Управление: прогрев при простое, выгрузка через N минут, лимит памяти, очередь запросов, таймауты.
- Метрики: tok/s, время до первого токена → показываем в разделе «Производительность».
- **Внешний провайдер (опция):** OpenAI-совместимый endpoint (base URL, модель, ключ), запросы через тот же интерфейс `LLMProvider`; таймауты, ретраи, лимит токенов. Включение — только вручную, с предупреждением и бейджем в результате (ADR-008).

## 10. Установка, переносимость, обновления

**Состав поставки (one-folder PyInstaller):**
```
AI Recogniser\
  AI Recogniser.exe          # shell + core worker (--core-worker)
  _internal\                 # CPython, зависимости, ui\dist, иконки, WebView2 .NET
  bin\ffmpeg.exe, ffprobe.exe, llama-server.exe
  data\                      # portable-режим; иначе %LOCALAPPDATA%
  models\manifest.json       # реестр (веса — отдельно)
```

**Установщик (Inno Setup):**
- Per-user, без UAC по умолчанию (`{localappdata}\Programs\AIRecogniser`), опция «для всех пользователей».
- Страницы: лицензия → компоненты → папка → данные → модели (чекбоксы с размерами и итогом) → автозапуск/ярлыки/контекстное меню → установка.
- Проверки: WebView2 (bootstrapper при отсутствии), .NET не нужен, свободное место, права на папку данных.
- Опции моделей: «только базовая» (214 МБ), «+ LLM 4B» (~2.6 ГБ), «+ LLM 8B» (~5 ГБ), «+ Whisper fallback» (~1.6 ГБ), «+ диаризация» (~35 МБ), «скачать позже».
- Uninstall: данные пользователя по умолчанию сохраняются (вопрос), модели — опционально.
- Подпись кода — при наличии сертификата; иначе предупреждение SmartScreen в инструкции.

**Portable:** zip-сборка, `portable.flag`, данные в `<папка>\data`, без реестра и автозапуска, работает с флешки (кроме первого запуска WebView2 на Win10).

**Обновления:** манифест `latest.json` (version, url, sha256, min_version, notes), проверка раз в сутки и по кнопке, скачивание в фоне, тихая установка с сохранением данных, каналы stable/beta. Откат — переустановка предыдущего установщика (данные совместимы через миграции).

**Офлайн-вариант:** `offline-bundle.zip` со всеми весами для машин без интернета; импорт моделей из папки/архива.

## 11. Экспресс-тест ПК и рекомендация моделей

**Что собираем:** CPU (модель, ядра, AVX2/AVX-512), RAM (всего/доступно), диск (свободно, SSD/HDD), GPU (имя, VRAM, драйвер, Vulkan/DirectML), WebView2, версия Windows, питание (ноут/ПК).

**Что измеряем на реальной нагрузке (не синтетике):**
1. ASR: 30-секундный русский сэмпл из поставки → RTFx, время.
2. LLM: генерация 128 токенов Qwen3-4B q4 → tok/s, TTFT.
3. iGPU: GigaAM на CPU vs DirectML EP — в M0 на коротком клипе DML проиграл (49.3 vs 56.8 RTFx, 622 vs 352 МБ); повторить на длинных файлах и решить, нужен ли DML вообще.
4. Диск: скорость чтения/записи 256 МБ (влияет на большие файлы).

**Выход:** `profile.json` + экран с tier (A/B/C) и объяснением: «Ваш ПК: 1 ч аудио ≈ 3 мин; рекомендуем GigaAM v3 e2e CTC + T-lite 8B q4; диаризация включена; iGPU-ускорение: выключено (прирост <10%)». Тест можно перезапустить; при смене железа — предложить заново.

## 15. Риски и mitigation

| Риск | Влияние | Что делаем |
|---|---|---|
| GigaAM хуже на шумной речи/музыке/акценте | качество | A/B на корпусе пользователя, fallback Whisper, выбор модели на задачу, отчёт WER |
| iGPU-ускорение нестабильно (DML/Vulkan) | скорость | CPU по умолчанию; ускорение — опция с бенчмарком; не блокирует релиз |
| Галлюцинации LLM в саммари | доверие | строгая схема, цитаты+таймкоды, extractive fallback, t=0.2 |
| Диаризация ошибается на пересечениях | UX | beta-пометка, ручное переименование спикеров, отключаемо |
| SmartScreen/AV на Python-приложение | установка | подпись, установщик вместо onefile, репутация, инструкция |
| Лицензии весов (T-lite/Yandex) | юридическое | проверить до релиза, оставить альтернативу Apache-2.0 (Qwen3) |
| Огромные модели/медленный интернет | onboarding | выбор размера, докачка, зеркала, офлайн-бандл |
| WebView2 отсутствует на старых Win10 | запуск | bootstrapper в установщике, проверка в мастере |
| Потеря данных при обновлении | доверие | миграции с бэкапом, тесты upgrade, «данные отдельно от программы» |
| Сложность поддержки двух процессов | разработка | health-check, авто-рестарт, структурированные логи, диагностика в один клик |

## 16. Фаза 2: серверный режим (задел уже в v1.0)

- Тот же `core` запускается как Windows-служба (или Docker на Linux) и слушает `0.0.0.0`.
- Веб-UI — тот же React-билд; добавляются: логин, роли, загрузка файлов из браузера, личные/общие очереди, квоты.
- Результаты — в сетевой папке (UNC), уведомление со ссылкой `\\server\share\...`; плюс e-mail/webhook (Telegram/Slack — опция).
- Аутентификация: локальные пользователи + токены, опционально AD/LDAP; HTTPS через reverse-proxy (Caddy) или встроенный сертификат.
- Админ-панель: очередь, воркеры, дисковое пространство, модели, аудит, статистика.
- Модель угроз: изоляция путей пользователей, лимиты размера, антивирус-скан входящих, rate-limit.
- Ограничение: 1 сервер = N воркеров ASR по CPU; горизонтальное масштабирование — позже (общая БД/очередь).

## Приложение A. Черновик API

Фактически реализовано в M1:

```
POST /api/v1/jobs                 multipart file          → 202 + job
GET  /api/v1/jobs                 список + прогресс
GET  /api/v1/jobs/{id}            детали, прогресс, текст
GET  /api/v1/jobs/{id}/result     скачать transcript.txt
GET  /api/v1/jobs/{id}/text       текст как text/plain
GET  /api/v1/rag/status           статус ragkb
GET  /api/v1/rag/search?q=&k=     поиск
POST /api/v1/rag/ask              {question, k} → ответ + источники
GET  /api/v1/settings             PUT /settings
GET  /api/v1/health               {version, status}
```

Планируется (M1+):

```
POST /api/v1/jobs/{id}/cancel|retry|pause
GET  /api/v1/jobs/{id}/export?fmt=srt|md|txt|json
GET  /api/v1/events               SSE: job.progress, job.done, job.failed
GET  /api/v1/models               установленные/доступные
POST /api/v1/models/{id}/download|import|remove
GET  /api/v1/kb/documents         POST /kb/documents (upload) · POST /kb/reindex
POST /api/v1/kb/search            {query, top_k}
POST /api/v1/chat                 {job_id, messages[]} → ответ + citations
POST /api/v1/bench/run            → profile.json + рекомендация
```

## Приложение C. Принципы промптов

- Роль: «аналитик, работающий строго по транскрипту».
- Жёсткий JSON-схема-контракт + пример; валидация и 1 ретрай.
- Каждый факт — с таймкодом; нет факта — `null`, не выдумывать.
- Отдельные промпты: `summary_map`, `summary_reduce`, `action_items`, `glossary_fix`, `qa`, `title`.
- Язык ответа = язык входа (RU по умолчанию), термины — из глоссария.
- Лимит контекста: явный бюджет токенов, обрезка по границам сегментов, never mid-sentence.
