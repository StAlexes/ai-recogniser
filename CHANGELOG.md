# Changelog

Все заметные изменения проекта AI Recogniser.
Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версионирование — [SemVer 2.0.0](https://semver.org/lang/ru/).

Правила ведения:
- Новая версия добавляется **сверху**, история не переписывается.
- Незавершённые изменения копятся в `[Unreleased]`.
- Дата релиза — ISO `YYYY-MM-DD`, версия в `pyproject.toml` должна совпадать с тегом `vX.Y.Z`.
- Раздел «Модели» фиксирует версии ASR/LLM/эмбеддингов и промптов, попавшие в релиз.

## [0.2.1] — 2026-10-27

### Fixed
- **Ошибка 500 при добавлении файла:** SQLite-схема заданий не мигрировала при обновлении
  (`table jobs has no column named source_path`). Добавлена автоматическая миграция колонок
  `source_path`, `summary`, `paused`, `segment_count` при старте ядра.
- **Пустой каталог моделей в exe:** манифест моделей теперь ищется и в `_internal/models`
  рядом с exe, и в корне репозитория при разработке.
- **Настройки не применялись:** убрана кнопка «Сохранить», изменения сохраняются
  автоматически с задержкой 400 мс и применяются к ядру сразу.
- **Дубль раздела «Модели»:** отдельная вкладка удалена, управление моделями осталось
  только в «Настройках».
- **Выход:** в поповере «О программе» кнопка «Выход» перенесена над информацией о версии,
  добавлен крестик «Свернуть в трей». Обе кнопки работают через JS-мост pywebview.

### Added
- **Автозапуск распознавания:** настройка «Распознавать файл немедленно при добавлении».
  Если выключена, задача остаётся в статусе «Ожидает запуска» с кнопкой «Запустить»
  (`POST /api/v1/jobs/{id}/start`).
- **Модели Ollama:** ядро определяет установленные модели через `http://127.0.0.1:11434/api/tags`;
  в настройках LLM появился провайдер «Ollama» и выпадающий список моделей.
- **Назначение модели:** поле `purpose` в `models/manifest.json` (расшифровка, саммаризация,
  вопросы, VAD-нарезка).
- **Версионирование сборок:** exe собирается в `dist/AI Recogniser <версия>/`, рядом
  создаётся `version.json` с версией, датой, git-коммитом и статусом рабочего дерева.
- **Контекстное меню:** скрипт регистрации сам находит самую свежую сборку в `dist`.

## [Unreleased]

### Added
- **M1, ASR:** рабочее распознавание mp3/mp4 и других аудио/видео форматов. ffmpeg приводит
  вход к 16 кГц mono WAV, `onnx-asr` лениво загружает GigaAM v3 e2e CTC int8 на CPU, прогресс
  передаётся по этапам «Подготовка аудио → Загрузка модели → Распознавание → Сохранение».
  Модель скачивается при первом запуске; после этого сценарий работает офлайн.
- **M1, отмена и повтор:** API `POST /api/v1/jobs/{id}/cancel` и `POST /api/v1/jobs/{id}/retry`.
  Отмена доступна для задач в статусе queued/running; повтор — для error/cancelled.
  Исходный файл хранится в `results/<job_id>/source<ext>`, поэтому задачу можно повторить
  даже после очистки временной папки. UI: кнопки «Отменить» (активные задачи) и
  «Повторить» (ошибка/отмена) в списке задач и в детальном просмотре.
- **M1, диаризация и экспорт:** добавлен разбор по участникам (Wespeaker embeddings +
  простая кластеризация по cosine similarity, опционально, выключено по умолчанию) и
  экспорт результатов в форматы **TXT / SRT / VTT / Markdown / JSON** с тайм-кодами.
  API: `GET /api/v1/jobs/{id}/export?format=...`.  Настройки диаризации (вкл/выкл,
  порог сходства, путь к модели) выведены в «Настройки».  Если модель диаризации
  недоступна, сегменты остаются без спикера, но распознавание работает.
- **M1, менеджер моделей:** каталог моделей (`models/manifest.json`), загрузка с
  проверкой SHA-256 и возобновлением, офлайн-импорт. API: `GET /api/v1/models`,
  `POST /api/v1/models/download/{id}`, прогресс скачивания, `POST /api/v1/models/import`.
- **M1, оповещения:** Windows toast-уведомления через иконку трея (pystray) с лог-фолбэком
  при завершении и ошибке задач.
- **M1, контекстное меню Windows:** `tools/register_context_menu.cmd` регистрирует
  «Распознать в AI Recogniser» для поддерживаемых расширений в HKCU (без прав админа).
  Файлы из контекстного меню добавляются в очередь при запуске приложения.
- **M1, VAD-нарезка:** Silero VAD v5 (ONNX, MIT) делит записи длиннее 30 с на речевые
  сегменты по паузам (по умолчанию до 30 с, пауза 300 мс, отступ 100 мс), сегменты
  распознаются по очереди и текст склеивается. Это снимает прежний лимит 300 с и ошибку
  GigaAM ONNX на длинных файлах. Если VAD-модель недоступна — резервная нарезка окнами
  по 60 с.
- **M1, SQLite-очередь:** состояние задач перенесено из in-memory + JSON в `data/airec_jobs.sqlite`
  (WAL-режим, `synchronous=NORMAL`). Задачи выживают при перезапуске ядра и падении процесса;
  unfinished-задачи при старте помечаются как прерванные с понятной ошибкой. Боковой файл
  `job.json` сохраняется для совместимости со сторонними инструментами.
- **Запуск и сборка через cmd:** `run.cmd` запускает решение из исходников «на лету» (проверяет
  venv, при необходимости собирает UI и открывает окно), `build.cmd` собирает нативный exe в
  `dist` и пробрасывает `-SkipUi`. `tools/build_exe.ps1` теперь заранее проверяет, что
  запущенный `AI Recogniser` не держит файлы `_internal`.
- **M1, очередь:** multipart-загрузка (`202`), фоновый worker, список/детали/результат/текст,
  `job.json` и `transcript.txt` в `data/results/<job_id>/`, восстановление завершённых задач
  после перезапуска через SQLite. Один worker; отмена и повтор — следующие шаги.
- **RAG-интеграция:** клиент `ragkb` (`/health`, `/search`, `/ask`) с таймаутами и понятными
  ошибками; API `GET /api/v1/rag/status`, `GET /api/v1/rag/search`, `POST /api/v1/rag/ask`.
  Индекс `ragkb` не копируется: приложение подключается к уже запущенному локальному сервису.
- **UI:** очередь подключена к реальному API (выбор файлов, запуск, polling, прогресс, текст,
  копирование и скачивание `.txt`); страница «База знаний» показывает статус, chunks, модель,
  latency, поиск и ответы с источниками; RAG-настройки выведены в «Настройки».
- **Сборка:** `packaging/airec.spec` включает `onnx-asr`, `onnxruntime`, `imageio-ffmpeg`,
  `python-multipart` и их данные; `AI Recogniser.exe` ~15 МБ, `_internal` ~211 МБ. Smoke-тест,
  распознавание mp3 и RAG status/search проверены в frozen-сборке без Python.
- **Проверки:** 32 теста (API, jobs, RAG, настройки), `ruff check app shell tools`, UI
  `tsc --noEmit` и `vite build`.
- **Vulkan-исследование:** `docs/VULKAN-NOTES.md` — почему GigaAM остаётся на CPU, где
  применим Vulkan в `llama.cpp` и почему WebGPU EP не является нативным Vulkan.
- План разработки `docs/PLAN.md` (v1.3): архитектура, модели, этапы, риски, критерии приёмки.
- Заведены версионирование (SemVer) и накопительный changelog.
- Зафиксированы решения 2026-10-23: стек Python + WebView2 + Fluent UI; локальная LLM с опцией внешних API; диаризация в v1.0 (beta).
- Рассмотрены GigaAM Multilingual и GigaChat Audio (публикация Сбера, 14.07.2026): Multilingual добавлен как опциональный ASR-движок (v1.0), GigaChat Audio — как post-1.0 эксперимент на GPU/внешнем API (ADR-009).
- **M0, ядро:** FastAPI-приложение с loopback-биндингом, случайным портом и сессионным токеном;
  `/healthz` (без авторизации), `/api/v1/health`, `/api/v1/settings` (GET/PUT с атомарной записью),
  `/api/v1/system/profile` (кэш `profile.json`), `/api/v1/models` (static-каталог), заглушка `POST /api/v1/jobs` (501).
- **M0, оболочка:** `shell/main.py` — окно WebView2, трей (pystray), закрытие в трей, single-instance
  через именованный mutex, управление жизненным циклом ядра, `--smoke-test`, `--autostart on/off/status`
  (HKCU Run; в portable-режиме реестр не трогается), иконка приложения (10 размеров).
- **M0, UI:** прототип на React 18 + TypeScript + Fluent UI v9 (Vite): очередь с drag&drop,
  база знаний, каталог моделей с профилем ПК, настройки (чтение/запись через API), светлая/тёмная тема,
  русская локализация, доступность с клавиатуры.
- **M0, измерения:** POC GigaAM v3 e2e CTC int8 на референсном ноуте (Ryzen 7 8845H):
  RTFx **56.8**, загрузка 1.7 с, peak RSS **352 МБ**, корректная пунктуация. DirectML (отдельный
  runtime, ORT 1.24.4) — RTFx 49.3 и 622 МБ RSS: iGPU Radeon 780M проигрывает CPU, дефолт CPU.
  Подробности: `docs/M0-NOTES.md`, воспроизводимый скрипт `tools/poc_gigaam.py`.
- **M0, нативная сборка:** PyInstaller one-folder (`packaging/airec.spec`,
  `tools/build_exe.ps1`) собирает `AI Recogniser.exe` + `_internal` без Python на целевой машине.
  В frozen-режиме оболочка запускает ядро тем же exe с внутренним флагом `--core-worker`,
  UI и иконки читаются из `sys._MEIPASS`, данные — из `%LOCALAPPDATA%` или portable-папки.
  Добавлены extra `build`, метаданные версии exe и `docs/BUILD.md`; opt-in `AIREC_DEBUG_PORT`
  для проверки WebView2 через CDP.
- CI: отдельные job'ы для ядра (ruff + pytest) и UI (typecheck + build); UI-job запускается,
  когда в репозитории есть `ui/package.json`.

### Changed
- `POST /api/v1/jobs` из заглушки `501` стал рабочим multipart-эндпоинтом; старый M0-контракт
  «пути + опции» заменён на загрузку файла и асинхронную задачу.
- Нативная сборка выросла с ~78 МБ до ~226 МБ (exe + `_internal`): внутри появились
  ONNX Runtime, ASR-зависимости и ffmpeg; это осознанная плата за offline-распознавание.
- Статус проекта: M0 завершён, M1 частично — сценарий «файл → VAD-сегменты → очередь → текст»
  уже работает; таймкоды, SQLite, отмена/повтор и SRT/VTT ещё не сделаны.
- Проект переведён на лицензию MIT (`LICENSE`, `pyproject.toml`); сторонние компоненты и модели
  перечислены в `docs/LICENSES.md`.
- Схема поставки уточнена: вместо отдельного `runtime\python.exe` используется one-folder
  PyInstaller-сборка, где shell и core worker — один и тот же exe (`docs/PLAN.md`).

### Fixed
- В frozen-сборке UI и иконки больше не ищутся относительно папки exe: добавлен
  `resource_root()` (`sys._MEIPASS`), поэтому окно и токен-хендшейк работают из любой папки.
- Полноэкранные оверлеи тултипов Fluent UI: `FluentProvider` копировал стили корня на mount-узлы
  порталов, из-за чего страницы с подсказками накрывались непрозрачным слоем. Отключено через
  `applyStylesToPortals={false}`; порталы по-прежнему получают переменные темы.
- Профиль ПК показывает физический GPU первым: виртуальные адаптеры (Parsec, VMware, Remote и т.п.)
  помечаются и уходят в конец списка.
- `config.json` с UTF-8 BOM (после сохранения в Блокноте) читается корректно, настройки не сбрасываются.
- Пустое состояние очереди больше не говорит «Очередь пуста», если ниже уже есть завершённые
  задачи; вместо этого предлагается добавить следующий файл.
- На странице «База знаний» убран literal-backtick вокруг адреса `127.0.0.1`.
- Длинные файлы больше не падают с `ONNXRuntimeError: ... Broadcast axis ... 5000 by 81999`:
  VAD-нарезка удерживает каждый сегмент в пределах позиционного лимита GigaAM. Если VAD
  недоступен, ядро автоматически переходит на фиксированные окна.

### Security
- Аудио и видео обрабатываются локально; RAG-запросы уходят только на явно настроенный
  локальный адрес. Внешние API не используются.
- **Лицензионный риск:** `imageio-ffmpeg 0.6.0` поставляет ffmpeg 7.1 essentials build с
  `--enable-gpl --enable-version3` (GPLv3), а не LGPL. До публичного релиза нужно заменить
  бинарник на LGPL-сборку или обеспечить GPL-совместимую поставку (исходники и тексты).

### Модели
- Фактически используется: `gigaam-v3-e2e-ctc`, quantization `int8`, runtime `onnx-asr`,
  provider `CPUExecutionProvider` (MIT).
- VAD: Silero VAD v5 ONNX (`istupakov/silero-vad-onnx`), MIT, ~2 МБ; скачивается при первом
  длинном файле и кэшируется.
- Внешний RAG: `ragkb` с индексом 11 959 чанков и генеративной моделью `gemma3:4b` (Ollama);
  в поставку AI Recogniser не входит.
- Планируется: multilingual-e5, T-lite-it-2.1 8B / Qwen3-4B (GGUF).
